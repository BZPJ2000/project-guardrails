# 流程固化：部署、测试、发版

流程性问题必须固化成文件，否则每次都要重新问一遍、每次都做得不一样。流程文件是**可执行的说明书**，不是散文。

## 每个流程 = 一份文档 + 一个脚本

```text
docs/flows/deploy.md     ← 人读：步骤、校验点、回滚
scripts/deploy.py        ← 机器执行：同样的步骤
```

文档和脚本步骤编号必须一一对应。改了脚本不改文档（或反过来），下次执行就会脱节。

## 文档固定章节

```markdown
## 用途
什么时候执行这个流程。

## 前置条件
需要什么权限、什么环境变量、什么服务在线。

## 步骤
1. …（含具体命令）
2. …

## 校验点
每步之后怎么确认成功（命令 + 期望输出）。

## 失败处理
- 症状 → 原因 → 处理

## 回滚
回到上一个可用版本的确切命令。

## 最后验证
2026-11-13 ｜ 谁验证的 ｜ 在哪台机器
```

## 上线流程最低要求

- **端口**：写死并记录，改动要留痕。
- **健康检查**：一条命令能确认服务起来了（curl + 期望状态码）。
- **日志位置**：出事时去哪看。
- **回滚命令**：一条命令回到上一版本，且验证过。
- **不带密码**：凭证走环境变量或密钥文件，文档里只写变量名。

## 更新触发条件

| 流程 | 什么时候必须更新 |
|---|---|
| 部署 | 端口/路径/环境变量/域名/依赖版本变化 |
| 测试 | 新增部件、新增单元、合格线调整 |
| 发版 | 版本号规则变化、产物位置变化 |
| 初始化 | 目录规范变化 |

把这些写进流程文档末尾的「维护」一节，否则流程会腐化成"上次有人这么干过"。

## 常用流程清单

- `flows/deploy.md` 部署到服务器
- `flows/test.md` 全量回归（`verify-all`）
- `flows/release.md` 打版本、打包、发布
- `flows/rollback.md` 回滚（可合并进 deploy）
- `flows/backup.md` 数据备份与恢复演练

## 一条判断

如果某个操作**第二次**需要解释"上次是怎么做的"，它就该变成流程文档。第三次还在口口相传，就是事故源。

# 注释规范：写给人，也写给下一个 AI

注释的标准不是"多"，是**接手的人不用读实现就能改对**。宁可 10 行有信息量的注释，不要 100 行复述代码的废话。

## 三层注释

| 层 | 写什么 | 谁看 | 强制 |
|---|---|---|---|
| 文件头 | 用途 / 关键词 / 输入 / 输出 / 文档 | 找代码的人 | 门禁强制 |
| 函数头 | 一句话做什么 + 参数含义 + 失败返回什么 | 调用方 | 公开函数强制 |
| 分支 | **为什么**这么写（约束、坑、业务规则） | 改这段的人 | 非显然分支强制 |

## 文件头

见 `navigation.md`。五行头之外，可选补一行 `不变量:`，写这个文件保证的、调用方可以依赖的性质：

```python
"""
用途: 按优先级排序任务
关键词: 排序, 优先级, scheduleSeq
输入: contracts/algo.json
输出: scheduleSeq (int[])
文档: docs/parts/algo.md
不变量: 全覆盖、无重复、序号从 1 连续
"""
```

## 函数注释

```python
def sort_tasks(tasks: list[dict], weights: dict) -> list[dict]:
    """按 priority 降序、同优先级按 age 升序排序。

    tasks 必须非空且每项含 priority(int 1-5)；
    weights 来自 params，缺键返回 E_UNKNOWN_KEY；
    空输入返回 E_EMPTY_INPUT。
    """
```

三件事：做什么、输入要求、失败怎么表达。不要写 `# 循环 tasks` 这种。

## 分支注释只写「为什么」

```python
# 优先级相同按年龄升序：老任务不能一直沉底（业务规则，见 docs/parts/algo.md）
key = (-t["priority"], t["age"])
```

```python
if not tasks:
    raise ContractError("E_EMPTY_INPUT")  # 空输入不是"排完是空"，是调用方错
```

不要写 `# 判断是否为空`——代码已经说了。

## 注释率

门禁按文件检查：**≥50 行的源文件，注释行占比不得低于 3%**（可配 `index.minCommentRatio`）。

注释行 = 以 `#` `//` `/*` `*` `--` 开头的行。这个阈值只防"一行注释都不写"，不逼你给每行加注释。

## 明确不写的

- 复述代码的注释（`i += 1  # i 加一`）
- 过期的 TODO（要么现在做，要么写进 `.agent/changes/`）
- 被注释掉的死代码（git 有历史）
- 密钥、真实姓名、手机号、内网 IP、绝对路径

## 注释和文档的分工

注释解释**这一行为什么这么写**；文档解释**这一块的契约和边界**。同一件事不要写两遍——写重了，改的时候必然只改一处。
